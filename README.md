# תהודה — מנתח אקוסטי לקערות טיבטיות

יישום רספונסיבי בעברית ובכיווניות מימין לשמאל, לניתוח אקוסטי של קערות טיבטיות באמצעות מיקרופון בדפדפן. הניתוח מתבצע במכשיר, מזהה עד שלושה רכיבי תדר יציבים ועוקב אחרי מעטפת נפרדת לכל רכיב. היישום מודד לחץ אקוסטי במיקרופון; הוא אינו מודד תנודה מכנית של הקערה.

## הפעלה

- נדרשת Node.js בגרסה 20 ומעלה.
- התקינו תלויות עם `pnpm install` (או `npm install`).
- הפעילו `pnpm dev` (או `npm run dev`) ופתחו את כתובת localhost שמוצגת במסוף.
- להרצת בדיקות DSP: `pnpm test` או `npm test`.
- לבניית גרסת הפצה: `pnpm build` או `npm run build`.

## פריסה ב־Vercel

הפרויקט משתמש ב־Vite. ב־Vercel בחרו **Add New → Project**, חברו את מאגר GitHub ובחרו את הפרויקט. Vercel יזהה את Vite; פקודת הבנייה היא `npm run build` ותיקיית הפלט היא `dist`. לאחר הפריסה, פתחו את כתובת ה־HTTPS ב־Safari באייפון ואשרו גישה למיקרופון.

אפשר לפרסם את האתר בכתובת Vercel גם כשהמאגר ב־GitHub פרטי. אין בפרויקט מפתחות API או משתני סביבה שנדרשים לבנייה.

הגישה למיקרופון מחייבת בדרך כלל HTTPS או localhost. באייפון מומלץ להשתמש בגרסה עדכנית של Safari ולפתוח את היישום דרך HTTPS. תמיכת `MediaRecorder`, פורמטי ההקלטה, קצב הדגימה, מספר הערוצים והגדרות העיבוד האוטומטי משתנים בין דפדפנים ומכשירים. היישום מבקש לבטל בקרת הגבר אוטומטית, ביטול הד והפחתת רעש, אך הדפדפן עשוי להתעלם מהבקשות או להוסיף עיבוד אחר. קצב הדגימה ומספר הערוצים בפועל מוצגים בתוצאה. קובץ ההקלטה המקורי אינו נשמר לאחר הניתוח.

## פרופילים ושמירה

מזינים שם או תיאור לקערה, מקליטים ובוחנים את התוצאה. מדידות שמורות נשמרות ב־IndexedDB של הדפדפן הנוכחי. הנתונים אינם מסתנכרנים בין מכשירים; פתיחת אותה כתובת באייפון אחר לא תציג מדידות שנשמרו במכשיר הראשון. מחיקת נתוני האתר או הדפדפן עלולה למחוק אותן. ייצוא CSV כולל סיכום של הרכיבים וההתאמות. ייצוא PDF וסנכרון בין מכשירים אינם זמינים עדיין.

## שיטת הניתוח ומגבלות

קוד עיבוד האות נמצא ב־`src/dsp.js`. הערוצים מומרצים לערוץ מונו לניתוח וממוצע ה־DC מוסר. זיהוי שיאי הספקטרום משתמש בחלון Hann, ב־FFT ובאינטרפולציה פרבולית על לוגריתם המשרעת. מועמדים נדרשים לבלוט לפחות ב־8 דציבל מהרקע המקומי ולהופיע בתדר דומה בלפחות שניים מארבעה חלונות. שיאים סמוכים מאוחדים באופן שמרני, ונבחרים לכל היותר שלושה לפי בולטות והתמדה.

לכל רכיב נבחר מחושבת מעטפת צרת־סרט עצמאית. במצבי הקשה מתאימים קו לאזור דעיכה מוקדם ומוגבל של המעטפת בדציבלים יחסיים, ומציגים שיפוע, קבוע זמן, R² וזמני T20/T30/T60 רק אם טווח הנתונים תומך בהם. T60 הוא אקסטרפולציה משוערת ולא זמן הדהוד שנמדד ישירות. סף הרעש הוא אומדן יחסי, לא מדידה מכוילת של רעש החדר.

שפשוף שפת הקערה הוא עירור מתמשך. במצב הזה מוצגים רכיבים יציבים, אך לא מחושב זמן דעיכה טבעי. זיהוי אוטומטי של רגע הפסקת השפשוף וניתוח הדעיכה שאחריו הם עבודה עתידית. סימון תדר יסודי אפשרי הוא שמרני: נדרשים שלושה רכיבים ביחסים קרובים למספרים שלמים. אם אין ראיות מספיקות, התדר היסודי אינו נקבע.

מרווח הבינים של ה־FFT שווה לקצב הדגימה חלקי גודל ה־FFT. אינטרפולציה יכולה לדייק את מיקום השיא, אך רזולוציית הבינים אינה ערובה לדיוק. החדר, מיקום המיקרופון, תגובת המכשיר, עיבוד הדפדפן, סטייה בתדר, רכיבים חופפים, דעיכה רב־שלבית, רעש והפרעות בזמן ההקשה משפיעים על התוצאה. בדיקות סינתטיות בודקות את התנהגות האלגוריתם, לא את כל שרשרת המדידה האקוסטית. היישום אינו נותן המלצות רפואיות או טיפוליות.

## מבנה הפרויקט

- `src/main.js` — ממשק בעברית, זרימת המדידה והקלטה מהדפדפן.
- `src/dsp.js` — קדם־עיבוד, FFT, בחירת רכיבים, מעטפות והתאמות דעיכה.
- `src/storage.js` — שמירת פרופילים מקומית וייצוא CSV בעברית.
- `src/style.css` — עיצוב רספונסיבי המותאם תחילה לטלפון ול־RTL.
- `test/dsp.test.js` — בדיקות סינתטיות לאלגוריתמי DSP.

אין לשמור בהיסטוריית Git הקלטות פרטיות או נתוני מדידה אישיים. קובצי `*.wav`, תלויות, קבצי בנייה ומשתני סביבה מוחרגים דרך `.gitignore`.
